# 박씨팜 자가 개선 절차서 (자가 발전 고리)

매일 아침 예약 작업이 이 절차를 그대로 실행한다. 고리 4단계: ① 재기 → ② 찾기 → ③ 고치기 → ④ 검증·되돌리기.
①②는 깃허브 작업이 이미 해 둔다(tools/self_check.py → private/metrics/날짜.json, site/data/selfcheck.json).
이 절차서는 ③④를 맡는다.

## 0. 준비
- 저장소 thecloudstay/bakssifarm 최신을 받는다(git pull --rebase).
- 오늘 숫자: private/metrics/ 의 가장 최근 날짜 파일. 「todo」 목록이 고칠 거리(높음→보통→낮음).
- 지난 기록: docs/개선기록.md.
- 깃허브 작업 상태: `gh api repos/thecloudstay/bakssifarm/actions/runs?per_page=10` 으로 아침 수집(daily)·국내 수집(korea) 성공 여부.

## 1. 매일 — 작은 고침 (하루 최대 3건)
고칠 거리 중 「높음」부터, 원인이 분명하고 되돌리기 쉬운 것만 고친다.
- 수집 실패: 오류 문구로 원인을 찾는다. 끝점·변수 이름·날짜 형식·쪽 넘김·시간 제한 같은 수집기 버그는 고친다.
  - 공공데이터포털 공통 주소(apis.data.go.kr)는 해외에서 막힌다 → 그런 수집기는 국내 실행기(korea.yml, 대표 컴퓨터)에서만 돈다. 국내 실행기가 꺼져 대기 중이면 고칠 것 없음(기록만).
  - 응답 칸 이름을 모르면 진단부터: tools/probe.py(국내)·tools/probe_ekape.py(우분투)를 고쳐 진단 작업 흐름(diag.yml, korea.yml 「force」)으로 돌려 tools/_debug/ 에서 확인한다.
- 빈 자료·오래된 자료: 원인을 찾아 고친다(경매 없는 날 처리, 파일 갱신 주기 등).
- 깨진 내부 연결: 대상 화면을 만들거나 연결을 바로잡는다.
- 화면 문구의 사실 오류(출처·날짜·단위)를 바로잡는다.
- 고친 뒤 해당 수집기·화면을 우분투에서 돌려 보고(가능한 것만) 커밋한다.

## 2. 매주 월요일 — 큰 개선 (최대 2건) + 지난 개선 평가
- 평가: docs/개선기록.md 에서 14일 전쯤의 「큰 개선」을 골라 전후 숫자를 비교한다(자료 줄 수·빈 칸 수·신호 적중률·방문 숫자가 있으면 방문). 나빠졌으면 그 커밋을 되돌리고 기록한다.
- 큰 개선 후보(숫자 근거가 있는 것만):
  - 구매 신호·위험 예보 기준 조정 — 적중 기록(site/data/buysignal.json score)이 10건 이상 쌓였을 때만, 근거별로 맞힌·틀린 비율을 보고 한 가지 기준만 바꾼다.
  - 새로 연동된 자료로 화면 칸 채우기(예: 도매시장 정산이 들어오면 경락가 화면·시세 한 장 칸).
  - 시군 화면에 빈 칸이 많은 갈래를 공공 자료로 채우기.
- 같은 화면의 큰 변경은 14일에 한 번까지.

## 3. 지켜야 할 선 (절대)
- 가격표·구독료·업체 상품·양식 문구·첫 화면 구성은 자동으로 바꾸지 않는다 → 「대표 확인 필요 제안」으로만 보고.
- 지어낸 숫자 금지. 확인 못 한 것은 「확인 필요」. 예시 숫자는 「예시」 표시를 지운 적 없게.
- 개별 농가·어가의 이름·위치·연락처를 새로 공개하지 않는다(가장 작은 단위는 리·읍면동, 업체 핀은 이미 공개 대상인 인허가 업종만).
- 열쇠·비밀값을 다루지 않는다. 대표 컴퓨터에 원격으로 아무것도 하지 않는다.
- 모든 변경은 커밋 하나로 되돌릴 수 있게, 커밋 메시지에 「자가 개선:」을 붙인다. 작성자 `git -c user.name="bakssifarm-bot" -c user.email="thecloudstay@gmail.com"`.
- 100% 한국어(화면·기록·보고 모두). 영어 단어·약자 금지.

## 4. 기록과 보고
- docs/개선기록.md 맨 아래에 한 줄씩: `- 날짜 | 작은/큰 | 무엇을 | 왜(숫자) | 커밋 | 2주 뒤 볼 숫자`.
- 바꾼 것이 있을 때만 대표에게 5줄 안으로 보고(오늘 고친 것 / 월요일이면 평가 결과 / 대표 확인이 필요한 제안·대표가 할 일). 바꾼 것이 없으면 보고하지 않는다.
- 대표가 할 일(활용신청·열쇠 입력 등)은 주 1회(월요일)만 묶어서 알린다.
